Assistant decisions
The entry point is a labelled control, not a bubble. “Ask about this job” sits in the page’s action row with ⌘K; on mobile it shares the action bar as a secondary. Never floating, never open on load. Scope is stated and changeable. A violet SCOPE row names the object — this job, this bullet, this milestone, my profile — so the user always knows what the answer is about. Suggested questions are page-specific and drawn from the verdict on screen. Four scope variants are specimened: Skip, Roadmap, Resume bullet, Profile. Answers cite their sources as the same sage evidence rows used on Job Detail and One Fix Away — repo, file count, CV line, JD requirement — so an answer is checkable, not authoritative. Answers end in product actions, not more conversation: Open the fix, Fix my CV wording. The assistant routes into REACH rather than replacing it. It cannot write. A standing footer note says suggested CV changes go through accept / reject — the assistant proposes, the review queue disposes. Loading is a skeleton plus a mono status naming what is being read. No typing dots, no thinking animation, no sparkles — consistent with the console’s observability model. Errors name the engine and confirm nothing changed, with Retry and the configured fallback. Engine identity appears only here and in Profile → Settings.
Identity is the 17–22px REACH pixel mark as the answer’s attribution — no avatar, no character, no glow, no dark surface. Still on the missing-asset list: a non-character assistant mark (object, not creature) to replace the wordmark in the attribution slot, and a citation glyph for source rows.
