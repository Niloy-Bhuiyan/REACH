The original extracted icons had zero transparency — every one carried a baked lavender or white rectangle and anti-aliased edges, so they showed as mismatched squares on any surface that was not exactly the bake colour. Backgrounds were flood-removed from the borders inward, fringe pixels cleared, and alpha hardened to 0 or 255. All nine screens now reference the restored set. ORIGINALS KEPT AT refs/px-*.png — UNREFERENCED
Scenery scene-path.png 720×360 — the stepping-stone progression band for Roadmap, with sage / apricot / stone stones matching the three node states. scene-path-390.png is the mobile crop; scene-profile.png the shorter Profile variant. Existing horizon*.png and hero-*.png remain the Home and header bookends. Scenery is opaque by design — it is only ever a background layer at 40–50% opacity behind a masked edge, never an inline object.
Third-party marks px-github, px-linkedin — evidence-source marks, legal anywhere an integration row appears. px-chatgpt, px-claude, px-codex, px-cloud — engine marks, permitted only on Profile → Settings, at 24–30px, inside a row. These are vector brand marks, not pixel art. That is deliberate and is the single sanctioned exception to the pixel family — it also keeps engines reading as infrastructure rather than as REACH’s own identity.

Interaction requirements

Non-negotiable behaviours. Motion clarifies state or causality, or it does not ship.
Motion — permitted
Console event append, 120 ms fade, newest last Console collapse into run summary, 200 ms height Drawer 240 ms slide from the right; sheet 280 ms from the bottom Opportunity Delta count-up on first reveal only, 400 ms, tabular numerals so width never jumps Milestone completion: node fill + rail colour, 300 ms Accepted diff collapses into the resume preview, 200 ms
Behaviour — required
Opening a job never unmounts the run or loses scroll position Every number over 24px has an inspectable derivation on the same screen No AI-proposed text reaches a document without accept / reject Assistant opens closed, scoped, and never on load Engine failure states name the engine and confirm nothing changed ⌘K opens the assistant scoped to the current object; Esc closes any overlay
Accessibility
Every status colour is paired with a word — colour is never the only cue Visible focus ring: 2px #6C63D8 at 2px offset, on canvas and on surfaces Drawers and sheets trap focus and restore it to the trigger on close Console is an aria-live polite region; it is not read event by event prefers-reduced-motion: count-ups resolve instantly, slides become fades, nothing else changes
Motion — forbidden
Looping or decorative animation of any kind Typing dots, thinking indicators, sparkles, glows Confetti, trophies, streaks, XP, level-ups Parallax or animated scenery Any motion that runs while the user is reading dense data

11

Data contract — freshness & Opportunity Delta

Eight rules. The screens already behave as if these are true.

Every one of these is visible somewhere in the design, so a different answer is not a configuration change — it changes what a screen is allowed to say. Design-required means the screen breaks its own promise without it. Assumed means the design picked a defensible value and will follow whatever engineering decides instead.

#RULEWHAT THE DESIGN ASSUMESWHERE IT IS VISIBLESTANDING
01Re-verification cadenceEvery posting in the active target is re-checked once per scheduled run, plus on demand when the user opens Discover more than 6 hours after the last run. A run verifies live status, not the full parse.Console event counts; “verified 2 h ago” stamps on every rowASSUMED
02Freshness bands≤ 24 h reads normally in stone. 24–72 h renders apricot and the word stale. Beyond 72 h the posting is shown but excluded from every count. Three bands, because the design only has three treatments.Discovery rows, Job Detail header, 12B stale bannerDESIGN-REQUIRED
03Disappeared postingsA posting that vanishes from source is retained 48 h, labelled no longer listed at source, then dropped. It never disappears from under a user mid-session, and it stops counting the moment it is flagged.Discovery row state; Delta drill-down listASSUMED
04Delta is computed per run, never client-sideBoth sides of the Delta are computed server-side at the end of a completed run and cached against that run id. The client renders a stored figure; it never derives one, so the same number cannot differ between two screens.Home, One Fix Away, Roadmap — all read 12 → 20, +8DESIGN-REQUIRED
05A partial run never moves a numberA failed or cancelled run writes no Delta and updates no count. The last completed run stays authoritative and is labelled as such.12B — “not counted toward your Opportunity Delta until a run completes”DESIGN-REQUIRED
06The audit set is stored, not reconstructedEach Delta persists the explicit posting ids of its before and after sets, with each one’s closing date. The drill-down is a lookup. If the ids are not stored, the audit table is a guess and the guarantee that every number is inspectable fails.One Fix Away audit table; Roadmap delta sidebarDESIGN-REQUIRED
07Predicted and realised are both keptThe predicted Delta is frozen at plan creation. The realised Delta is computed from the first completed run after the last milestone closes. Both persist, and the difference is explained by naming the postings that entered or left the set.12E — realised +9 against predicted +8, with the reasonDESIGN-REQUIRED
08Evidence-source staleness is separateSource sync age is tracked per source and shown as stale past 14 days. It never blocks a run and never marks a posting stale — evidence freshness and posting freshness are different clocks and are never merged into one indicator.Profile, Settings, 12F — “an engine problem never touches your evidence”ASSUMED
CLOCKS All timestamps are stored UTC and rendered in the user’s local zone, in IBM Plex Mono with tabular numerals. Ages under an hour read in minutes, under a day in hours, then in days — never a bare date, because the point of the stamp is recency rather than history.
